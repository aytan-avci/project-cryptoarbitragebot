# Crypto Arbitrage Agent

A modular, multi-exchange crypto arbitrage bot, designed for development with
**Claude Code in VSCode** under disciplined agentic engineering principles.

> **Status:** Specification. No live trading. Paper-trade by default.
> **Capital risk:** This is a tool for software development practice. Crypto
> trading can lose 100% of your capital. Read [§ Safety](#safety) before any live use.

---

## Why This Repo Exists

Manual crypto arbitrage is effectively dead — price gaps close in milliseconds because
thousands of bots are already hunting them. A serious arbitrage system in 2026 must:

1. Detect price gaps across venues in real time (WebSocket, not polling).
2. Subtract fees, slippage, and latency *before* declaring an opportunity.
3. Pass every order through a risk layer.
4. Recover gracefully from exchange outages, partial fills, and stuck orders.
5. Log everything for tax, audit, and post-mortems.

This repo is the specification and skeleton for such a system, structured so
that **Claude Code** can implement and extend it without breaking the design.

## Design Method: ADD (Attribute-Driven Design)

We drive architecture from **quality attributes** (performance, reliability,
security, modifiability, testability, observability), not from clever code patterns.

Each architectural decision is traceable to a numbered scenario in
`specs/QUALITY_ATTRIBUTES.md`. If you cannot point to a scenario, the decision
does not belong in the architecture.

ADD steps applied in this repo:

1. **Identify architectural drivers** — `specs/ARCHITECTURE.md § 1`
2. **Choose a design concept (decomposition pattern)** — `§ 3`
3. **Instantiate architectural elements** — `§ 4`
4. **Allocate responsibilities** — `§ 5`
5. **Define interfaces** — `§ 6`
6. **Sketch views** — `§ 7`
7. **Analyze trade-offs** — `§ 8`

## Agent Discipline: Karpathy's Four Principles

Every action Claude Code takes on this repo passes through four gates:

| # | Principle | One-liner |
|---|---|---|
| 1 | **Think Before Coding** | Don't assume. Don't hide confusion. Surface tradeoffs. |
| 2 | **Simplicity First** | Minimum code that solves the problem. Nothing speculative. |
| 3 | **Surgical Changes** | Touch only what you must. Clean up only your own mess. |
| 4 | **Goal-Driven Execution** | Define success criteria. Loop until verified. |

Full definitions: `CLAUDE.md § 1`.

## Supported Strategies (MVP picks one)

| Strategy | Risk | Capital efficiency | MVP order |
|---|---|---|---|
| **Funding-rate arbitrage** (single exchange) | Lowest | Medium | Recommended first |
| **Triangular arbitrage** (single exchange) | Low | Medium | Second |
| **Spatial / cross-exchange arbitrage** | Medium–High (transfer risk) | High | Third, after rebalancing logic exists |
| **CEX–DEX arbitrage** | High (gas, MEV) | Highest | Out of MVP scope |

Build for **one strategy at a time.** Universal bots that do all three never work.

## Getting Started — Run the Bot (Faz 6 MVP)

The paper-trade MVP runs end-to-end on synthetic snapshots:

```bash
# 1. Project-local virtualenv (no system-wide pollution)
python3.11 -m venv .venv
.venv/bin/pip install -e ".[dev]"

# 2. Run the agent — one iteration, all defaults
.venv/bin/python -m arbitrage_agent
```

Expected output (one JSON line per event to stdout):

```
{"event": "agent.start", "iterations": 1, "mode": "paper", ...}
{"event": "opportunity.detected", "expected_net_profit_usd": "0.658199", ...}
{"event": "risk.approved", "reason": "all checks passed", ...}
{"event": "execution.submitted", "order_ids": [...], ...}
{"event": "execution.fill", "exchange": "binance", "side": "buy", ...}
{"event": "execution.fill", "exchange": "bybit",   "side": "sell", ...}
{"event": "agent.complete", "opportunities": 1, "approved": 1, "fills": 2, ...}
```

The audit trail lands at `logs/decisions.jsonl` (one JSON line per
`opportunity_detected` / `risk_decision` / `fill`). `logs/` is gitignored.

Override defaults via env vars (`.env` or shell) — example:

```bash
PIPELINE_ITERATIONS=5 SPATIAL_SIZE_BTC=0.005 .venv/bin/python -m arbitrage_agent
```

Run the suite (`184 passed`):

```bash
.venv/bin/python -m pytest -q
```

### One-time security setup (recommended)

The repo ships pre-commit hooks that scan every commit for leaked
secrets (see `specs/SECURITY.md § S1`). Operator setup:

```bash
brew install gitleaks         # macOS
pip install pre-commit         # any platform
pre-commit install             # registers the git hook
```

After this, `git commit` automatically runs `gitleaks --config=
.gitleaks.toml` on staged files; the CI workflow at
`.github/workflows/security.yml` re-runs the same scan on every push.
A second pre-commit hook (`scripts/check_env_example.py`) verifies
that `.env.example` never holds a real credential — the file is a
TEMPLATE only; real values live in `.env` (gitignored).

### Live exchange — testnet first (Faz 7b)

Per `specs/SECURITY.md § S7`, a new exchange runs on testnet for at
least 30 days before mainnet is enabled. Faz 7b ships authenticated
Binance support; for testnet:

```bash
# 1) Create a Binance testnet account at https://testnet.binance.vision/
# 2) Generate API key with Spot Trading ENABLED, Withdraw DISABLED.
# 3) Put the key into .env (NEVER .env.example):
#    BINANCE_API_KEY=...
#    BINANCE_API_SECRET=...
# 4) Point at testnet:
#    BINANCE_REST_BASE_URL=https://testnet.binance.vision

EXECUTION_MODE=live BINANCE_ENABLED=true \
  BINANCE_REST_BASE_URL=https://testnet.binance.vision \
  .venv/bin/python -m arbitrage_agent
```

The S5 probe (`_ensure_no_withdraw_permission`) refuses to operate if
the key has Withdraw permission. The S4 model_validator refuses live
+ mainnet without `LIVE_TRADING_CONFIRMED=true` (do NOT set this for
testnet — it's a separate explicit step for mainnet, much later).

## Safety

- **Do not connect a key with withdrawal permission.** Ever.
- **Run in paper-trade mode (`EXECUTION_MODE=paper`) until you have ≥30 days of
  stable behavior on real market data.**
- **Start with the smallest position size the exchange allows when going live.**
- **Crypto markets are adversarial.** Slippage, exchange downtime, partial fills,
  and MEV can erode or invert "profitable" spreads. Most paper-profitable
  strategies lose money in live conditions for the first iterations.
- **You are responsible for tax reporting** in your jurisdiction. The bot logs
  every fill — use those logs.
